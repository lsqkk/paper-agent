# 阶段五：苛刻审稿与修改

## 前置准备

读取 `report.md` 和 `docs/workflow_rules.md`（六项文风规范）。

## 5a. 图片就位确认

读取 `/img` 下的图片文件，确保已按Markdown格式正确插入 `report.md`。

## 5b. 独立 Agent 审稿

使用 Agent 工具（type: general-purpose）启动一个独立的论文评审子任务。
Agent 脱离当前上下文，以独立视角评审，避免自我审稿的认知偏误。

**Agent prompt 须包含以下完整指令**：

> 你扮演一位极其严厉的毕业论文评审老师。请读取 report.md 的全部内容，从以下五个维度进行批判性评审。直接在 /img 下查看对应图片。将结果输出为 review.md，每条意见必须标注具体位置（章节、段落）和修改建议。
>
> **五维度标准**：
> 1. **逻辑与论证**：论点跳跃、因果关系弱、概念偷换、论证不充分
> 2. **文风规范**：逐条检查 six 项规范（禁用分点/说教句式/标题冒号/引号/长度错落/英文注释），规则参见 docs/workflow_rules.md
> 3. **事实与引用**：数据过时、引用张冠李戴、结论过度夸大、编号遗漏或错误
> 4. **结构均衡性**：各章节字数是否合理、是否某一节过长或过短
> 5. **跨章一致性**：术语前后统一、论点不自相矛盾、前文承诺后文有兑现
>
> **输出格式**：每条意见包含 `[维度] [严重度: 高/中/低] [位置] [问题描述] [修改建议]`

主流程等待 Agent 完成后，读取其输出的 `review.md`。

## 5c. 针对性修改

基于 `review.md` 逐条修改 `report.md`。采用**靶向修改**原则：
- 仅重写被评审意见涉及的具体段落或章节
- 无需修改的部分保持原样
- 修改后的版本保存为 `report_revised.md`

同时更新 `review.md`，在每条意见旁标注"已修改"或"未修改（理由）"。

## 5d. 用户反馈

输出 `review.md` 和 `report_revised.md` 后，附上一句简短的修改总结（如"共修复了X条意见，主要涉及Y章节的重写"），并请求用户反馈：

"请审阅修改后的报告。如无异议请回复'定稿'；如有进一步意见，请具体说明。"

## 5e. 循环机制

若用户提出新意见，回到 5b 重新审稿（可基于已有 review.md 做增量审查），直至用户回复"定稿"或类似表达。
