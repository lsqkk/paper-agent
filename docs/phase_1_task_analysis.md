# 阶段一：任务解析与方案确认

## 执行步骤

### 1. 读取任务要求

读取仓库根目录下的 `【任务要求.md】` 文件，提取全部作业参数：主题、字数、格式、内容侧重点、参考文献要求等。

### 2. 任务类型分类

根据提取的参数判断任务类型，从以下模板中选择对应的结构基底：

| 类型 | 默认结构 |
|------|---------|
| 课程论文/总结报告型 | 引言 → 分主题论述 → 总结 |
| 文献综述型 | 引言 → 主题分类综述 → 研究空白 → 展望 |
| 实验/研究报告型 | 引言 → 方法 → 实验设置 → 结果分析 → 讨论 → 结论 |
| 读书报告型 | 引言 → 作者观点梳理 → 批判性分析 → 个人思考 → 总结 |

### 3. 联网预搜索（可选）

进行3-5次关键查询，了解研究现状、可用数据集或争议焦点。
将搜索结果整理到 `pre_search.md`，每条包含：标题、链接、核心发现、可对应的大纲方向。
此步骤结果将在阶段二中复用。

### 4. 设计方案并生成大纲

大纲须包含以下要素：

**内容定位**：核心论点、论述角度、预期创新点。

**目录结构**：至少到二级标题，标注每个板块的核心功能（如"引入问题—综述文献—提出方法—实验分析—结论展望"）。

**字数预算表**：为每个二级板块分配预期字数及占比，确保总和接近任务要求字数。示例：

| 章节 | 预期字数 | 占比 |
|------|---------|------|
| 1 引言 | 800 | 10% |
| 2 文献综述 | 2000 | 25% |
| 3 方法论 | 1600 | 20% |
| 4 结果分析 | 2000 | 25% |
| 5 讨论 | 800 | 10% |
| 6 结论 | 800 | 10% |

**展开策略**：每个板块计划采用的论述逻辑（对比、因果、递进等）和所需支撑类型。

**资料搜需**：列出后续搜索的5-10个关键词及信息类型（综述论文、顶会文章、统计数据、开源代码等）。

### 5. 生成初步大纲

保存为 `初步大纲.md`。内容比最终报告粗粒度，但逻辑链条完整，且附有字数预算表。

### 6. 请求用户确认

输出大纲后，**必须停止**，并明确请求用户确认或提出修改意见。等待用户回复后，按反馈修改大纲，直至用户明确表示"满意，进入下一阶段"。

> **停止点**：本阶段末必须等待用户确认，不得自动继续。
