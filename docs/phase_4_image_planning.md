# 阶段四：图片规划与处理

## 前置准备

读取 `report.md` 确定图片需求。

## 4a. 判断图片需求

通读 `report.md`，标记出"如果有一张图会更清晰"的位置。原则上每个主要章节最多一张图，全文不超过5张。

## 4b. 图片类型与处理方式

| 类型 | 举例 | 处理方式 |
|------|------|---------|
| 技术示意图 | 流程图、框图、时间线、架构图、层级图、原理图、对比图 | 自行绘制SVG |
| 改编图 | 根据论文数据或实验结果重绘的统一风格图表 | 自行绘制SVG |
| 真实影像 | 历史照片、实拍设备图、人物肖像、软件界面截图 | 创建 `img.md` 让用户提供 |

## 4c. 技术示意图绘制规范

1. **选择模板**：绘制前读取 `docs/svg_template.md`，为每张图选择合适的模板（单色/双色/三色）
2. **严格遵循模板**：使用模板定义的色板、字体层级、元素样式
3. **文件命名**：`img_01_描述性英文.svg`、`img_02_描述性英文.svg`
4. **文字约束**：所有文字严格位于框体/列边界内，不得溢出
5. **标注语言**：以中文标注为主，关键技术术语可中英双语
6. **尺寸**：宽度800-1000px，高度300-560px

## 4d. 质量校验

每个SVG生成后，读取 `docs/svg_checklist.md` 并逐条检查：

- 文件完整性（xmlns声明、viewBox正确、无解析错误）
- 文字可读性（不溢出、字体后备链、字号层级一致）
- 配色规范（使用模板色板、对比度充足）
- 结构对齐（框体对齐、连接线准确、边界留白）
- 图文一致性（信息匹配、术语统一）

**所有条目通过后**方可插入 `report.md`。

## 4e. 插入图片

使用Markdown格式插入：

```markdown
![图X：标题](img/img_0X_描述性英文.svg)
```

检查正文中是否有显式引用该图（"如图X所示"）。缺少引用的图片需补充文字引用。

## 4f. 继续条件

若全部为自绘SVG，直接进入阶段五。
若需用户提供图片，等待用户回复"图片已放置"后进入阶段五。
